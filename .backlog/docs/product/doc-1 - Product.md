# 产品现状

队列与管理台定向核对日期：2026-10-25；其余历史功能证据日期为 2026-10-07。版本：0.5.0。待办与阶段规划以 `.backlog/tasks/` 和 `.backlog/milestones/` 为准；历史证据见 [验收记录](<../notes/doc-2 - acceptance_2026-10-07.md>)，迁移实施说明由 Backlog 的 TASK-1 维护。本次没有重跑历史测试，也没有用户逐项验收结论。

## 定位与环境

面向 Windows 和 Linux 的单用户 ECMWF/CDS 下载管理工具，以 CLI 为主要入口，兼顾 Linux 服务器和本地使用，要求 Python 3.11+。用户可通过 CLI 管理请求、任务与账号，在需要时启动后台服务并通过浏览器使用管理台。

后端监听本地 HTTP 端口，同源提供 API 与生产构建的 React 页面，Typer CLI 直接复用应用服务。服务器只需绑定 `127.0.0.1`，通过 SSH 端口转发在本地浏览器访问；本地运行时直接访问回环地址。管理台不要求单独启动 Vite，也不要求将服务开放到局域网或公网。

| 环境与用途 | 产品目标 | 当前实现与验证边界 |
| --- | --- | --- |
| Linux 服务器 | CLI 优先；后端可在后台运行；按需通过 SSH 隧道访问 Web | 当前 Linux/WSL 代码及本地服务已验证；具体服务器托管方式仍需文档与场景验收 |
| Windows 本地 | 原生 CLI 与同一套后台后端、Web 管理台 | 属于目标支持范围；目前 SecretStore 使用 POSIX `fcntl` 文件锁，Windows 原生兼容与验收尚未完成 |
| Linux 本地/WSL | CLI 与回环 Web 管理台 | 当前技术验证覆盖；WSL 通过不能替代 Windows 原生验收 |

本次用户已确认服务器采用 SSH 端口转发，保持回环监听。完整跨平台和后台运行需求另存 Drafts 供审查；当前不改监听配置，也不直接承诺已完成 Windows 兼容。

## 核心流程

1. 配置 CDS 账号；密钥进入权限为 `0600` 的 `config/secrets.yaml`，公共账号 DTO 不返回密钥。
2. 指定 `dataset_id + request_payload`，预览输出路径和拆分结果，创建任务。
3. 创建成功即进入同一个 queued 队列，由 Web 内置 Worker 或独立 `ecmwf worker` 按并发上限自动消费；CLI 提交退出不代表消费者已启动。
4. 文件写入 `.part`；成功后原子重命名，保存状态和事件。
5. 查看任务、请求取消，或在失败后重试。删除任务记录不删除下载文件。

## 管理台现状

管理台收敛为任务队列、添加任务、账号、设置四个入口。概览和下载活动合并到唯一队列页面；旧首页及活动地址跳转到队列。删除展示性的工作区切换、固定健康栏、步骤条、批量选择、更多操作、全部入队、停止调度和未接线的模板控件。

- 队列：真实状态统计、搜索、状态筛选、20 条分页、任务详情、取消及失败后重试。排队任务显示账号或并发等等待原因；无内置消费者时提示需运行独立 Worker。没有手动入队和暂停入口；历史 pending 可查看与取消，不自动启动。
- 添加任务：输入数据集 ID，粘贴可编辑的 JSON 参数，保留数组、数字和布尔值等类型。输出目录、按数据日期拆分与 AI 建议折叠显示。预览不创建任务且不等同 CDS 校验；只有添加并下载一个提交入口，忙碌时防止重复提交，错误留在表单中显示。
- 账号：卡片展示实际状态，支持新增、连接测试、编辑、禁用和确认删除。新建默认可用，移除未生效的新建禁用选项；每次打开表单重新初始化，密钥不回填，测试与保存失败有反馈。
- 设置：只读展示后台实际配置的输出目录、并发上限、失败重试、数据库与 AI 启用状态，不伪造健康或密钥配置结果。运行中的调度器参数需重启后生效。

服务连接、内置调度器和并发使用实际 API 状态。独立 Worker 不属于本服务内置调度器，不能据内置状态断言独立 Worker 未运行。前端 lib 目录补充 Git 忽略例外，使实际 API 模块纳入版本管理。

本轮定向后端测试 24 项通过；前端 TypeScript 与 Vite 构建通过。Playwright 在独立临时数据库、虚拟账号和无消费者实例中验证队列搜索/筛选/分页/详情/取消、JSON 校验、预览无写入、提交直接 queued、账号编辑和设置、旧路由跳转及窄屏导航。控制台仅出现主动模拟 422 错误请求的预期资源错误，未发现框架运行错误。按用户约定没有截图或视觉验收；真实 CDS 下载、Windows 原生与科学内容验收仍不在这些结果中。

## 已知限制与风险

- 取消只在 `retrieve` 和 `download` 前后检查，不能立即中断远端排队或传输；不支持暂停。
- `stop()` 不等待运行中的下载线程就释放租约；失去租约后没有阻止旧 Worker 继续写入的机制。
- 过期任务只在启动时恢复；启动时任务租约尚未过期的遗留任务可能持续停在 running。
- 配置更新先写文件再校验，无效配置可能影响下一次启动；具体修复登记在 Backlog。
- 输出扩展名尚未完整考虑 `download_format=zip`。
- 正常账号响应不含 key，但异常、HTTP 校验错误和日志的全链路脱敏尚未验收。

0.5.0 使用全新数据库，不导入旧 YAML/JSON 历史，不自动删除旧配置或已有下载文件。截至本轮记忆迁移，没有新增真实 CDS 下载或科学内容检查通过证据；账号为空是 2026-10-07 的检查结果，不能推定为 2026-10-23 的实时配置状态。

当前启动通过 SQLAlchemy `create_all` 创建缺失表；重新打开已有数据库保留任务记录。该路径不自动更改已有表的列，不提供版本升级或回滚脚本。后续若确需改变数据库结构，须另行确认数据处理方案，不能自动删除或重建用户数据库。


## 单一队列与兼容边界

DRAFT-3 已于 2026-10-25 经用户确认，TASK-15、TASK-17 实施后交用户验收：新任务创建直接写 queued，不再支持仅创建/手动入队；调度器与账号可用时自动消费，不承诺 CDS 远端立即开始。保留并发上限、失败自动重试及历史查询，不提供定时、暂停或全局停止。

旧 CLI --enqueue 作为隐藏兼容参数接受，旧 task enqueue/run 和 API enqueue 仍可显式处理历史记录，但不出现在主要帮助/接口文档与 Web 界面中。API 创建传 enqueue=true 仍接受，enqueue=false 返回 422；应用服务创建不再接收 enqueue 参数。历史 pending、配置和下载数据不自动变更，不重建数据库。

取消尚不能立即中断远端 retrieve/download；取消被事务接受后，不进入下一次自动重试，不发布成功文件。取消早于 Worker 执行或晚于最后一次传输检查的边界均有定向回归覆盖。后台租约切换与可靠故障恢复仍按 TASK-10、TASK-11 单独跟进。
