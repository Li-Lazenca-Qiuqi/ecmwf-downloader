# PRD：仅提交请求、监视远端作业并返回下载链接

## 用户决定与审查状态

2026-10-27 用户明确要求移除软件内的数据下载：软件只提交请求、监视状态并返回下载链接，由用户自行使用专业下载器传输文件。
用户已确认按本版实施并明确取消 ARCO 本地导出；实施由 TASK-32 跟踪，尚待用户验收。本轮不提交 Git、不改版本、不发布。

## 产品边界

主流程：编辑数据请求 → 按需要拆成多个请求 → 自动提交 → 监视远端排队/处理 → 返回真实结果链接。
完成只表示远端结果与下载链接已就绪，不表示文件已下载。
保留 Windows/Linux CLI + 本地回环 Web、服务器 SSH 端口转发、账号、官方数据集目录、通用字段编译校验、AI 补全、只读请求预览和手动规模估算。
不启动下载器、浏览器下载、代理下载接口或本地数据文件导出；不接管外部下载进度。复制链接与 API/CLI 输出链接为本次交接方式，不加入下载器 RPC 集成。

## CDS 提交与监视

使用已经安装的 ecmwf-datastores-client 的独立 submit、get_remote、get_results 和 Results.location 能力；显式 cleanup=False，不能获取链接后自动删除远端作业。
submit 成功立即持久化 remote_request_id 与提交账号关联；后续查询始终使用该账号，不能轮换为其他账号查询同一作业。
区分本地待提交、提交中、远端排队、远端处理中、链接就绪、失败、取消和结果失效；远端不给处理百分比时只显示真实状态，不伪造百分比。
服务重启通过已保存的远端 ID 继续查询，不重新提交已知作业；同一工作区仍只能有一个调度器消费新请求。
轮询临时失败与重新提交严格分开：前者可退避重试，后者不能因为一次查询失败或提交响应不明确而盲目新增远端请求。提交结果不明确时显示待核实，给用户明确处理入口。
保留单一队列、自动提交、取消和明确的失败重试；不恢复暂停、定时下载和手动入队。
取消已提交请求时尝试官方作业删除/取消，按实际响应显示结果；确认前不声称远端已停止。已就绪结果不因结束监视或正常退出而被删除。

## 结果链接

每个请求保存并展示来源、请求 ID、真实结果 URL、官方提供的文件名/大小/类型及更新时间；API、CLI 与页面可读取、复制单条或批量就绪链接。
结果按列表建模；当前已安装 SDK 的 Results.asset 为单一 asset，不假设其他来源或将来的响应永远只有一项。
不为获取大小而读取文件体；只读取 API、目录等元数据。无元数据的大小/有效期留空或显示未提供，不估造成已知值。
CDS 结果缓存可能清除，链接不承诺永久有效。不默认写死 24 小时或其他时长；仅显示服务实际给出的过期信息。
提供重新查询结果入口：远端结果仍在则更新链接；已不可用则标明失效，由用户选择重新提交，不自动制造新请求。
CDS API Key 仅用于 API 认证，不嵌入下载链接。日志和普通状态事件不输出认证头或带签名的完整结果链接；用户明确获取链接的本地接口正常返回真实 URL。

## 镜像范围建议

CDS 为默认来源，正常提交和监视远端作业。
NCAR AWS 与 NCAR GDEX 继续列出真实目录、选择原文件，直接返回相应 HTTPS 文件链接，不下载文件、不假造远端处理过程。来源与文件对应关系保持可追踪。
现有 Google ARCO 路径依赖本机读取 Zarr 并生成 NetCDF，和新边界冲突。建议本次移除该本地导出能力，并暂时从可提交来源中移除 ARCO。
Google ARCO 官方另有 raw 文件目录；本草案不推断其可替代任意时空子集，也不把 Zarr 根地址冒充所选子集的 NetCDF 下载链接。若需要接入 raw 文件链接，应单独明确实际目录与选择规则。

## 界面与 CLI

添加页保留数据集、字段、AI、手动规模和请求预览；移除输出目录及浏览、覆盖设置、文件路径预览，按钮改为“提交请求”。
年月日拆分继续用于拆分远端请求，右栏改为“请求拆分与提交”，预览展示子请求数量与参数摘要。
任务列表改为请求队列，展示远端排队/处理/链接就绪、请求 ID、来源和提交时间；详情展示结果链接与官方元数据，支持复制链接。
移除传输进度、已下载字节、速度、下载完成和本地输出位置等含义。设置保留请求并发/轮询/查询重试配置，去除下载目录和覆盖选项。
CLI 提供提交、状态/监视和链接输出；不再提供本地数据下载、输出目录、覆盖选项。包名、ecmwf 命令和版本本次不改名。

## 存储和现有数据

推荐在当前 SQLite 中建立新的请求任务/远端作业记录表，通过现有 create_all 只创建缺失表，避免自动修改或重建已有表。
保存编译后的请求、账号关联、远端 ID/状态、结果链接元数据和恢复所需时间信息；不能把内部字段塞进提交给 CDS 的科学参数。
已有账号、配置、任务记录和下载文件不清空、不重跑；旧下载记录不伪装成新请求结果。旧表与文件如需物理清理，先列出清单和影响另行确认。
不引入 Alembic、不制作旧数据快照、不新增重复迁移报告。确认后的实施计划细化新表字段、接口和旧数据展示边界。

## 拟移除的实现范围

application/worker.py 中 DownloadEngine 的数据传输、.part、文件进度监视、目标发布和文件残留清理，改为请求提交及监视职责。
infrastructure/cds.py 的 retrieve/download 文件链路，改为远端请求和结果元数据适配；保留账号认证能力。
infrastructure/mirrors.py 的 NCAR 文件流写入、签名/长度下载校验和 ARCO 本地 NetCDF 导出；保留 NCAR 目录与真实文件 URL 生成。
RequestPage、QueuePage、SettingsPage 及 CLI/API 中的本地下载设置与字段；DirectoryPicker 和只服务本地输出目录的接口/服务在核对引用后移除。
下载专用测试、依赖按引用核对后调整；不批量删除包含仍有效目录、字段、账号或请求逻辑的模块，不删除用户数据及无关改动。

## 验收范围

1. CDS 模拟 accepted/running/successful/failed/rejected、查询临时失败、结果失效和取消；本地状态与用户操作一致。
2. 保存远端 ID 后重启/租约切换能继续查询，不重复提交；提交结果不明确不能盲目自动重试。
3. 单一与多结果链接正确返回，空结果不标就绪；来源文件名、大小、类型及未知有效期如实展示；过期后不会自动重新提交。
4. NCAR AWS/GDEX 所选文件返回真实 HTTPS URL，不请求或保存文件体；ARCO 本地导出不可调用。
5. 页面、CLI、API 无本地输出目录、覆盖、传输进度或自动下载入口；拆分、字段、AI 与手动规模保持适用功能。
6. 定向测试拦截 SDK download/retrieve 与数据文件 GET/写入，确认请求流程只处理控制与元数据；现有用户数据不变。
7. 真实验收沿用用户已选择的 ERA5 single levels 小请求（2m temperature，2024-01-01 00:00 UTC，31°N–30°N/120°E–121°E，NetCDF），只提交、轮询并取得结果链接。既有“下载内容验收”证据不代替新流程；不下载数据文件，不冒称所有数据集/Windows 已验收。
8. 只做相关功能检查及必要构建，不主动截图/视觉验收或运行无关全量测试。
