## 1. 目标、范围与依据

为 CDS 和当前镜像建立统一的字段编辑方案：根据每个数据集的真实元数据自动组织界面、校验选择、生成请求预览和任务；遇到新控件、缺失表单或元数据冲突时，准确说明支持范围。

依据为 2026-10-26 的全量调查：145 个 CDS 目录条目逐项查询，144 份表单成功、1 项 form.json 返回 404；144 份表单含 1268 个节点、10 种官方控件。另核对 NCAR AWS、NCAR GDEX 与 Google ARCO。数量和结构依据见 [doc-3 调查记录](<../docs/notes/doc-3 - 数据集表单字段调查与展示规则依据.md>)。调查覆盖公开表单结构，未覆盖所有约束组合或实际下载结果。

本稿为用户已批准实施的完整通用设计，实施由 TASK-30 跟踪；当前实现与测试证据见 Product，用户验收仍单独进行。

### 适用范围

- 当前全部可取得表单的数据集，统一读取和解释字段，不维护固定 ERA5 参数清单。
- 当前全部来源采用相同的选择、提示、校验与预览框架，各来源声明自己的下载和拆分能力。
- 后续新增数据集只要使用已有类型和已核实的请求编码，即可复用；出现新类型时进入统一的待适配流程。
- 保持单队列、添加后自动开始、取消、后台本地监听和 SSH 转发的既有路线；本方案不需要数据库表结构变化。

## 2. 设计原则与优先级

依次判断：来源能力 → 字段含义 → 分组与激活条件 → 单选/多选 → 实际请求格式 → 默认值和约束 → 选项规模 → 显示样式。

单选按钮、下拉框、列表是呈现方式；单选或多选是选择能力；字符串、数字、数组是请求格式，三者分别建模。例如界面只选一个变量，而 API 要求数组时，提交的是单元素数组。调整排版不能改变选项 ID、数值类型或请求能力。

官方控件、表单的分组引用、Process 描述、已核实的官方 API 示例共同作为依据。来源不一致时记录冲突；不通过名称猜测请求编码，也不因为某份描述缺项就直接丢弃字段。具体适配器必须有可复核依据和定向测试。

## 3. 统一处理流程

1. 根据来源与 dataset_id 获取目录、表单及可用的请求描述，区分在线、缓存和失败。
2. 将原始元数据规范化为结构模型，完整保存字段与分组关系。
3. 校验引用、重复标识和类型，生成明确的适配诊断。
4. 根据分组默认分支和字段默认值初始化编辑状态。
5. 按展示规则渲染当前激活的字段，查询有效选项约束。
6. 用户修改或 AI 回填后，重新计算激活分支、校验结果与最终请求。
7. 使用同一请求编译器生成右侧预览和拆分计划；实际创建任务时后端重新校验。
8. 校验通过后按既有行为入队下载。没有可编译请求时，指出具体原因和对应字段。

Web、AI 和 CLI 复用同一份字段定义和后端编译/校验逻辑；前端校验用于及时反馈，后端负责最终检查。

## 4. 统一数据模型

| 模型 | 必需信息 | 职责 |
|---|---|---|
| SchemaDocument | source_id、dataset_id、revision、fetched_at、metadata_source、support_status、diagnostics | 标识当前元数据及支持程度 |
| FieldSpec | node_id、field_id、label、kind、selection_mode、required、default、options、bounds、help | 描述用户如何编辑，不假定与请求参数一一对应 |
| GroupSpec | node_id、group_kind、children、default_branch、branch_labels、order | 保存互斥或布局关系 |
| RequestBinding | codec_id、output_keys、wire_types、contract_status、evidence | 描述界面值怎样转换为 API 参数 |
| CapabilitySpec | file_selection、spatial_modes、time_modes、split_strategies、output_formats、constraints_support | 声明该来源和数据集实际能力 |
| EditorState | draft_values、active_branches、touched、selection_revision | 保存当前输入及切换前的草稿 |
| CompileResult | request_payload、errors、warnings、field_mapping、schema_revision | 供预览、AI 校验、拆分和创建共同使用 |

revision 是本次字段定义的内容标识，用于识别是否发生变化，不是项目版本号。RequestBinding 中的 codec 是有测试的转换函数，例如将四个方向的输入转换为 API 规定顺序的数组。

### 模型约束

- 区分 node_id 与最终参数名；说明、标题、分组和虚拟控件不自动成为请求键。
- options 保留原始值及类型、名称、顺序和全部分类关系；去重时按类型和值判断，保留月份前导零。
- 区分默认值、允许输入范围、数据覆盖范围、最小/最大子集范围。
- 区分无输入、显式空值、0、false 和空数组；是否允许空值由对应约束决定。
- children 支持名称引用及嵌套结构，统一解析成节点关系；同一字段的多分类归属不产生重复参数。
- 引用缺失、循环、重复标识存在冲突时输出定位诊断，不靠相邻顺序补猜。纯显示问题与影响提交的问题分开标记。

## 5. 控件映射与显示规则

| 元数据类型 | 显示规则 | 请求与校验规则 |
|---|---|---|
| StringChoiceWidget | 1–4 项用单选按钮，5 项以上用下拉，超过 10 项可搜索 | 保持单选；最终按 RequestBinding 输出标量或单元素数组 |
| StringListWidget | 不超过 12 项显示复选网格，更多时搜索和滚动选择 | 保持多选能力，序列化为对应数组，不把一个已选项自动变成标量 |
| StringListArrayWidget | 按官方分类折叠，展示分类与字段的已选数 | 完整保留多分类关系，同值跨分类同步并只提交一次 |
| DateRangeWidget | 开始日期、结束日期两个输入 | 验证真实日历、起止顺序、允许日期边界；编码通过已验证转换器完成 |
| GeographicExtentWidget | North、West、South、East 四坐标输入 | 按本数据集允许边界、子集大小限制和请求顺序校验 |
| GeographicLocationWidget | Latitude、Longitude 两输入 | 仅激活该分支时参与编译，按已核实的单点编码转换 |
| ExclusiveGroupWidget | 单选或分段控件，下方显示当前分支 | 解析 children 和 default，分组自身不作为请求键 |
| ExclusiveGroupAccordionWidget | 使用同一互斥组组件，按元数据展示分支标题 | 与上一种采用同一激活、必填和参数清理规则 |
| FreeEditionWidget | 组内无参数分支合并为分支说明；独立说明附到相关字段或说明区 | 不作为普通输入，不一律隐藏；保留单位、层次及下载指引 |
| LicenceWidget | 页面底部集中提示条款名称与官方入口 | 不作为请求参数，不宣称已接受条款 |
| JSON Schema string/number/integer/boolean | 对应文本、数字、整数或布尔选择 | 检查类型、有限数、边界及明确的格式要求，禁止将布尔值当数字 |
| JSON Schema enum/array | 根据允许选取数量使用单选或多选 | 保留原始类型，遵守 items、minItems、maxItems 等已解释的约束 |
| JSON Schema object/条件结构 | 对已支持的结构生成字段组 | 无法解释的结构进入待适配状态，不以通用文本框代替结构校验 |
| Heading 或纯布局 | 合并为对应段落标题 | 不参与请求编译 |
| 未知控件 | 展示清楚的尚未支持提示 | 未激活可选分支不影响其他路径；激活或必需的未支持字段阻止提交 |

单一候选的必填项显示固定值摘要。优先使用官方合法默认值；没有默认值且当前唯一合法候选已确认时可以初始化，并清楚显示。可选项仍允许不设置，不因候选只有一个而自动加入请求。

数量阈值是集中配置的产品初始值。超过约 100 项的列表按需渲染可见项，搜索、滚动和键盘仍可访问全部候选；不可截断候选。原生分类默认展开状态可以作为提示，长分类显示摘要，搜索自动展示命中的分类。

## 6. 选项搜索与批量操作

- 支持名称、ID 和分类搜索，搜索不修改现有选择。
- 显示总候选数、当前合法候选数和已选数；已选值在搜索结果之外时仍可查看和取消。
- 全选操作明确标为全选当前可用结果并显示数量，清空支持整个字段或当前分类。
- 禁用项继续可辨识，展示其与当前选择不兼容的状态；不自动选择禁用项。
- 跨分类的同值共享状态，批选、撤销及序列化使用同一去重规则。
- 选项增加或约束变化时保持当前搜索与可定位的选择状态；字段定义变化后重新检查值是否仍有效。

## 7. 时间参数规则

区分离散日期、连续日期范围、整点/时间值、预报时效和统计周期，不按名字中是否含 time 就统一使用同一种控件。

1. year、month、day 的单选或多选能力服从元数据。年份区间快捷选择最终展开为实际合法选项，缺失年份不补造。
2. 月份和日期保留官方值，例如 01；只在内部校验时转换为数字。
3. 离散选择与连续区间分别展示，避免把不连续日期扩成连续请求。
4. DateRange 使用真实日历和官方 minStart/maxEnd；有默认起止时显示实际跨度，不能把默认大范围隐藏起来。
5. 日期范围的闭区间/开区间语义、时区和最终参数编码由绑定说明，未确认时不猜测、不自动拆成 year/month/day。
6. 整点、小时、季节、period、leadtime 等沿用官方精度、单位与候选，不统一假定为逐小时。
7. 来源明确使用 UTC 时注明 UTC；其他情况不自动按浏览器本地时区转换。

## 8. 空间参数与互斥分支

只显示元数据实际提供的模式，例如完整范围/区域，或单点/区域。默认分支由官方定义或已核实的来源配置决定；没有默认分支时提示用户选择，不擅自默认全球。

完整范围表示数据集全部可用覆盖。区域默认值仅是输入建议，不能据此推断全球覆盖，也不能据覆盖范围自动填写默认子集。

- 区域显示 North、West、South、East；请求中的坐标顺序由绑定决定，不由界面排列推断。
- 单点显示 Latitude、Longitude，遵守该数据集的坐标范围。
- 经度可采用不同范围和跨日界线规则；按来源能力解释，不能统一强制为 -180～180 或统一要求 West≤East。
- stepX/stepY 用于输入步进和提示，只有明确约束时才强制网格对齐；不自动修改用户坐标。
- 最小和最大区域大小按数据集定义验证，边界错误就近提示。
- 切换分支后，仅激活分支的当前值参与校验、约束查询、AI 当前选择和最终 payload；切回时可恢复页面内暂存的输入。可用分支的定义仍可提供给 AI，以支持用户要求切换模式。
- 激活分支需要完整输入，即使原始子字段没有 required 标记，也不能把缺少坐标的分支当作已完成。
- 日期等非地理互斥组复用同一规则，不能统一解释为完整地理范围。

示例：普通 ERA5 提供完整范围/区域；ERA5 时间序列提供单点/小区域且默认单点。两者共用分组机制，通过各自元数据生成不同模式。

## 9. 默认值、约束与异步更新

初始化按顺序执行：解析分组 → 选取合法默认分支 → 读取激活字段的官方默认值 → 本地校验 → 查询选项约束。无合法默认值时保留未设置状态。

约束有三种结果：可用、来源不提供、查询失败。来源不提供约束不是失败；失败不能伪装为所有组合都已验证。

- 约束请求以 source_id、dataset_id、schema_revision、激活选择和账号作用域作为标识，不把密钥放入缓存键或输出。
- 每次修改递增选择标识，旧请求返回后不得覆盖新选择；取消等待和丢弃过期结果采用相同规则。
- 已选值变为无效时保留可见并标出冲突，禁用提交，允许用户取消或修改，不静默替换。
- 查询失败时仍显示已知元数据和本地错误，标明远端组合尚未核实。若合同编码已确认且本地有效，可以按既有产品策略提交，由远端实际判定；已知无效项和编码未确认项仍阻止提交。
- 同时只依据当前完整选择计算约束，避免前端多个字段各自改写同一份全局候选。

## 10. 请求编译与预览一致性

RequestCompiler 接收字段定义、编辑状态和来源能力，输出唯一的 CompileResult，供预览与创建共用。

编译顺序：解析当前分支 → 提取激活输入 → 校验值及组合 → 通过 codec 转换真实参数 → 检查参数冲突 → 生成最终 payload。

- 分组、标题、帮助、未激活分支和页面草稿不进入 payload。
- 标量与数组按真实绑定生成，保留数字、布尔和字符串差异；无输入不默认输出 null。
- 多个界面字段写同一请求键时，只有转换器明确支持的合并才允许；冲突必须定位说明，不能按最后一个覆盖。
- 表单与 Process 描述出现差异时，只读元数据不能单独证明正确编码。日期和单点适配应核对官方生成的 API 示例或转换逻辑，再以定向用例验证。
- 缺失 Process 描述不自动判定整个数据集不可用；已有已验证绑定仍可使用，未确认部分单独诊断。
- 预览显示实际 payload、来源、任务数和输出路径。与当前字段定义或选择不一致的旧预览不用于创建。
- 创建时提交 schema_revision 和当前状态/参数，后端重新检查。CLI 直接提供 payload 时也进入相同的最终参数校验路径；定义变化或参数不一致时返回可修正的错误。

当前 ERA5 时间序列的 Process inputs 没有完整列出表单中的 date/location；实施已核对官方前端转换：DateRange 为 [start/end]，location 为 latitude/longitude 对象。依据和验证见 Product。

## 11. 来源能力、输出与拆分

| 来源 | 参数界面 | 输出与拆分能力 |
|---|---|---|
| CDS | 官方字段、互斥组与约束驱动 | 格式服从数据集，只有已支持的日期绑定才能按年/月/日拆分 |
| NCAR AWS | 本站产品/月目录与文件表格 | 每文件一任务，下载原格式，不提供动态裁剪或日期拆分 |
| NCAR GDEX | 自有目录与文件表格，独立于 AWS 查询 | 同为原文件下载，来源独立记录，输出名与 AWS 区分 |
| Google ARCO | 实际变量分类、产品版本、日期整点、区域、压力层 | 按已发布覆盖范围读取并导出 NetCDF；支持已有年月日拆分能力 |

NCAR 文件表格显示文件名、来源给出的大小、已选状态与汇总；目录近似大小与精确字节分开标识。未知大小显示未知，不据文件名补造变量或裁剪字段。

输出目录浏览指向后端机器，使用现有能力。日期拆分必须由 verified splitter 声明，具有明确的区间端点、日历和编码规则；仅出现名为 date 或 period 的字段不足以启用拆分。拆分计划不能引入用户未选日期、重叠区间或遗漏日期。预览显示实际任务数，创建复用同一拆分结果。

继续沿用不覆盖既有文件、.part 发布和既有取消/重试规则。目录表格中勾选多个原文件不改变原文件内容。

## 12. 页面组织、说明与操作可达性

继续采用左侧参数和输出、右侧 AI 与请求预览。左侧保留官方依赖顺序，将相邻同类输入组织成清楚的产品、时间、空间和格式段落；模型、实验、成员和版本等不丢失、不套固定模板。

标题显示可读名称，字段 ID 作为辅助信息；说明、错误与字段建立对应关系。长帮助默认折叠，影响当前选择的范围限制和错误就近展示，必填输入不能藏在说明内。

纯标题合并，FreeEdition 的单位说明、层次说明和下载指引按含义附到字段或独立说明区。无法可靠归属时保留一处可展开说明，不按名字猜归属后丢掉内容。条款集中显示名称、相关入口与必要提示，不假定用户已经接受。

搜索、单选、分类展开、已选项取消和坐标输入支持键盘操作。窄屏将 AI/预览接到表单之后，分组仍能完整操作；列表不通过横向溢出隐藏候选。

## 13. AI 与 CLI 的统一行为

AI 上下文包含当前数据集、可用分支及各分支受支持的字段定义、合法候选和必要限制；当前选择仅包含激活分支的值，不发送未激活分支的旧草稿。大候选集超过模型上下文时，应先检索相关候选并明确范围；不能静默裁掉候选后声称完整覆盖。

AI 返回建议先校验 UI 字段、组分支和类型；分支切换及对应字段建议作为一个整体校验和应用，再经过同一编译器生成请求。非法、过期和未支持的建议不应用；提供撤销。切换分组时按组规则移除未激活参数，预览同步。

CLI 查询可输出字段、分组、来源能力和适配诊断；直接 payload 与 Web 生成的 payload 都由同一绑定和校验逻辑处理。服务配置继续在设置页，参数补全继续位于右侧预览上方。

## 14. 缓存、失败与适配状态

字段定义保持进程内缓存，沿用可刷新的元数据获取方式；缓存按来源、数据集、目录、账号作用域和定义内容区分，不创建原始响应历史快照。

每个数据集有 full、partial、unavailable 三种适配状态，并另外展示 online、cache、error 元数据来源：

- full：当前定义的全部节点可以分类，需要的请求编码已确认；不等于所有组合或下载验收已通过。
- partial：部分控件、分支或编码待适配；明确标出受影响范围，只允许完整受支持的有效路径。
- unavailable：没有可用于编辑的字段定义，或当前没有任何可编译路径；展示错误原因、重试和官方入口。

404 只表示未获取到表单，不推断站点停止服务或永远不可下载。刷新失败时可显示已有缓存及时间；没有缓存时不造候选。未知可选字段不能按普通文本框默默提交，必需且不支持的字段明确阻止提交。

## 15. 模块职责与接口调整

| 位置 | 职责 |
|---|---|
| domain/schema.py | 与来源无关的字段、分组、能力和诊断模型 |
| infrastructure/datastores.py 与来源适配模块 | 获取原始元数据、规范化来源结构、提供已核实的绑定信息 |
| application/datasets.py | 编排读取、缓存、定义标识与适配状态 |
| application/request_compiler.py | 激活分支、验证、请求编码和参数冲突检查 |
| application/request_builder.py | 基于已编译参数和来源能力生成输出及拆分计划 |
| interfaces/http 与 interfaces/cli | 暴露同一份模型和编译结果，校验输入，不复制来源规则 |
| frontend/features/request | 字段渲染器、分组控制器、选择列表、文件表格和帮助组件 |
| frontend/requestFields.ts | 轻量即时校验与 UI 状态处理，最终结果以后端编译为准 |

内置控件通过简单的类型到适配函数映射注册。通用类型优先；确有来源差异时集中在来源适配器中，并注明依据与用例，避免分散在页面组件中。

沿用现有 /api/v1 接口，在 schema、预览和创建 DTO 中补充结构、能力、诊断及 revision；同一实施阶段同步 Web、CLI 和 AI 调用方，避免分别维护冲突的解释逻辑。请求转换仅生成既有任务 payload，不需要增加数据库列。

外部元数据按数据处理：文本安全显示，链接校验协议和来源；转换函数由项目代码提供，不执行元数据中的代码，也不把凭据放入 DTO、日志或报告。

## 16. 实施顺序与交付单元

### P1 结构模型与来源规范化

完成所有已观察控件分类、字符串 children 引用、组默认值和说明归属；以当前可获取全目录检查分类覆盖。交付结构化 schema 和定位诊断，先解决当前扁平模型的信息丢失。

### P2 请求转换与后端校验

核对日期范围、单点和其他虚拟字段的真实编码，建立绑定及编译器；明确单选与请求数组的区别、分支清理及参数冲突。未确认的编码保持 partial，不以猜测格式推进验收。

### P3 通用编辑器与来源能力

实现统一控件选择、互斥组、时间/空间输入、分类和长列表；NCAR 切换为文件表格，ARCO 与 CDS 按实际能力显示；保留现有排版和设置入口。

### P4 联动、AI、预览与拆分

接入版本化选择标识、约束更新与过期防护，统一 AI/CLI 校验、预览和创建；仅对已确认的时间绑定启用拆分。

### P5 覆盖检查与用户验收

核对完整当前目录的分类与诊断，完成代表性功能验证，列出 full/partial/unavailable 的实际结果和缺口，再交用户验收。全量元数据验证与定向回归分别记录，避免每次改动重复所有下载测试。

## 17. 验收标准

1. 当前成功获取的全部 144 份表单可以分类，每个节点都有明确角色；遗漏、冲突和 404 有准确诊断。
2. 10 种已观察官方控件有明确展示和转换路径；不能确认的编码在实际结果中列为 partial，不能计入 full。
3. 单选/多选能力和 wire 类型分别验证，字符串 01、数字、布尔和数组不发生无意转换。
4. 两种互斥组、日期组、完整范围/区域和单点/区域都按真实引用、默认分支及能力工作；旧分支不残留在请求中。
5. 日期边界、真实日历、空间范围及最大/最小子集校验正确，未声明的全球模式、时区和拆分能力不出现。
6. 全部候选可访问，单候选、跨组重复、861 项时效和长年份列表仍可搜索、批选、取消与键盘操作。
7. 约束失效、失败和过期响应有正确反馈；有效输入不被静默修改，已知无效组合不能提交。
8. AI 回填、撤销、CLI、Web 预览和后端创建对同一选择生成一致的最终参数；预览不包含说明、分组或未激活输入。
9. NCAR 两站点只提供各自真实目录与原文件能力，ARCO 和 CDS 保留各自已核实的子集及格式限制。
10. 默认值、条款、单位说明和下载指引可见且无重复包装；重要限制不只藏在长说明中。
11. schema 刷新或切换数据集后旧状态、约束、AI 结果和预览不会应用到新定义；创建期间不被并发编辑改写。
12. 当前用户数据、凭据、既有文件、队列语义和监听配置不受影响，所有日志和响应不输出密钥。

验证采用当前元数据的只读分类核对与各语义的精简测试用例；不保存全目录原始表单快照。界面交互仅做相关功能验证，不默认开展视觉验收。需要真实下载验证时另列最小请求、来源、预估流量和内容检查。

验收标准不在本轮勾选；所有任务最终由用户验收并标记完成。提交、版本与发布分别等待对应明确授权。
