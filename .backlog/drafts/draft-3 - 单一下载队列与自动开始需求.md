## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
## 目标与用户决定

2026-10-25 用户决定简化任务管理：只维护一个下载队列，任务加入后自动开始；不选择下载时间，不提供暂停，不想要的任务直接取消。产品继续面向 Windows/Linux，以 CLI 为主要入口，Web 管理台复用相同服务。

## 行为与范围

1. CLI、API、Web 创建任务成功后统一进入可消费的队列，不再让用户选择仅创建、稍后入队或预约下载。预览仍可在提交前检查请求与拆分结果，不产生任务。
2. 一个工作区只有一个共享队列，沿用现有并发上限；不是限制为一次只下载一个任务。调度器运行且有可用账号和空闲槽位时自动取任务，槽位满时排队。加入队列不保证 CDS 远端立即开始传输。
3. 保留后台 Worker/Web 调度器的部署方式；CLI 提交后退出不应被描述为后台服务已经启动。消费者未运行、账号不可用等情况应明确显示等待原因，不伪装成下载中。
4. 不提供暂停、恢复、停止整个队列、手动全部入队等控制。队列中的任务可直接取消；运行中的任务展示取消中，停止后展示已取消，不能立即伪装为已取消或下载完成。
5. 本次不取消现有失败自动重试策略。失败后的手动重试直接返回同一队列，取消后的任务不自动重试。前端不使用暂停图标表达排队或取消。
6. 收敛创建入口为添加并下载，移除仅创建、创建并入队的二选一。取消与删除任务记录分开；取消不删除已完成文件，历史查询保留。

## 当前实现差距

TaskService.create、TaskCreateBody 和 CLI 创建默认 enqueue=False，先产生 pending；Web 创建传 enqueue=True，但仅创建按钮实际只调用 preview。没有用户预约时间字段，也没有后端暂停状态。claim_next 已从一个队列按创建时间取任务并沿用并发限制。

取消目前只在 CDS retrieve/download 前后检查，无法立即中断远端排队或传输。实施应保证取消后不再自动重试、不把结果发布成成功文件，并如实显示取消中；主动中断远端请求的能力须根据 adapter 实际接口验证，不能直接承诺秒级取消。

## 实施边界与关联

- 关联 TASK-15：旧验收要求仅创建保存 pending，与本需求冲突。审查本草稿后重写该任务，避免继续实现旧流程；TASK-17 中全部入队、停止调度等控件范围同时收敛。
- 不因简化流程删除或重建数据库，不改现有下载文件，不批量启动历史 pending 任务。实施前明确旧 API/CLI 入队入口和历史 pending 的兼容处理；本轮需求整理不触碰这些数据。
- 不扩大到 Windows 原生锁、后台服务安装器或 TASK-9 至 TASK-14 的全部可靠性修复；分别沿用原任务，单一队列不代表这些问题自动解决。

## 验收条件

- CLI/API/Web 的新任务无需二次入队；有运行中的消费者和资源时自动被领取。
- 并发已满时等待，空位释放后继续消费；没有预约时间、暂停或全局停止入口。
- 预览不创建任务；创建失败清晰反馈，不产生伪成功提示。
- 排队及重试等待中的任务取消后不被领取；运行中的任务正确经过取消中，最终不自动重试或误记完成。
- 历史任务、凭据与已下载文件保留；兼容策略明确且不暗中启动旧任务。
- 用隔离目录和模拟 CDS 做定向服务/API/CLI 与取消验证；前端做类型检查和构建。真实 CDS 下载另按 TASK-9 验收，不自动做视觉测试。
