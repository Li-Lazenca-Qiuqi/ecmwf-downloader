# Windows/Linux CLI 与后台管理台

状态：待用户审查。日期：2026-10-25。来源：用户明确产品面向 Windows 和 Linux，以 CLI 为主要入口；后端后台运行；服务器管理台采用 SSH 端口转发，服务仅需本地回环监听。关联：TASK-25。

## 已确认的产品定位

- Python 3.11+，Windows 和 Linux 均为目标平台；以 CLI 执行请求、任务、账号和配置操作。
- Linux 服务器是主要使用场景之一，应可不启动 Web 而独立运行 CLI/Worker。
- Web 是同一工作区的可选管理入口：后台 FastAPI 服务通过本地 HTTP 端口提供 API、SSE 与生产构建前端。
- 服务器监听 127.0.0.1，通过 SSH 转发后由本地浏览器访问；本地使用时直接访问回环端口。
- 保持单用户/单工作区模型，同一数据库只允许一个调度器持有租约；用户关闭浏览器不等于停止后端。

## 使用场景

| 场景 | 期望行为 |
| --- | --- |
| 服务器纯 CLI | 无图形环境即可管理任务，独立 Worker 消费队列 |
| 服务器管理台 | 后端后台运行，SSH 隧道把远端回环端口映射到本地回环端口 |
| Windows 本地 | 原生终端运行 CLI/后端，本地浏览器访问同源管理台 |
| Linux 本地或 WSL | 沿用相同应用服务与数据格式，在本机回环地址访问 |

## 功能与支持要求

1. 明确两个平台的安装、配置目录、任务与输出路径规则，含带空格路径；保持凭据不进入公共 DTO 和日志。
2. Windows 原生环境具备跨进程凭据文件保护及原子替换；Linux 保留文件锁和 0600 权限要求。不得通过取消锁来规避兼容问题。
3. 提供可验证的后台启动、持续运行、日志查看和停止方式；可使用各系统已有进程管理，不预先承诺新增服务安装器。
4. 后台服务仅监听回环；SSH 转发的本地端也绑定回环，端口可按占用情况选择。无需直接 IP/端口暴露，无需新增公网认证体系。
5. CLI 与 Web 共享 SQLite、配置和账号，避免重复调度；生产管理台无需 Node 或独立 Vite 服务。

## 当前差距与证据边界

- SecretStore._lock 目前直接导入 fcntl，不能据 Linux/WSL 测试宣称 Windows 原生可用。
- 现有 CLI web/worker 是长运行进程；产品内置后台托管能力未验收，需要明确并验证运行方式。
- CLI 独立、同源 Web、回环限制已有实现；SSH 方案本次获用户确认，但未实际连接用户服务器验收。
- 当前产品仍有调度可靠性与管理台操作缺口，继续由既有 TASK-9 到 TASK-21 跟踪；本草稿不把这些事项标记完成。

## 验收范围

- 在 Linux/WSL 与原生 Windows 分别验证安装、CLI、账号保存、数据库初始化及已有记录保留；使用虚构凭据验证正常与失败路径保护。
- 在明确的后台运行方式下验证 CLI/Web 协同、浏览器关闭后后端持续运行和可控停止，保留单调度器语义。
- 在可用 Linux 服务器上通过 SSH 转发验证管理台、API 与 SSE；不更改防火墙或开放非回环监听。
- Windows 原生与服务器 SSH 场景的证据分别记录，不以 WSL 或本地 HTTP 验证代替。
- 只做明确功能的定向验证；用户验收并手动设置完成状态。

## 范围边界
